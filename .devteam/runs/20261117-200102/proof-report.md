### Architect: design

The change is a local reorder inside the existing mobile card renderer (src/UI/MobileView.tsx) plus a rule swap on the existing .mobileExpandRow CSS module class, and a one-row documentation correction. No new component, hook, prop, type or dependency is introduced: the chevron keeps its existing <span role="button"> with tabIndex, aria-expanded, Enter/Space handler and data-rt-ignore-row-click, and simply moves from before the card-body div to after it, still inside the same .card div and still under the same `expandRowRenderer && rowHasContent` guard. Because MobileDetailSection already renders immediately after the card under the same guard, the moved row lands directly above the panel it opens with no empty row and no change to open/close behaviour. Left alignment comes from the existing justify-content: flex-start, so it is untouched. R2 is satisfied by changing margin-bottom/border-bottom to margin-top/border-top in .mobileExpandRow, keeping display:flex, align-items:center, justify-content:flex-start and padding: 0 0 0.25rem 0. R4 is satisfied by construction: .mobileExpandRow is referenced only by MobileView, and the desktop chevron cell (DesktopView expandColumn) shares no class with it, so the CSS edit cannot leak into desktop. Cost and scale: no new dependencies, no state, no effects, no listeners, no data-shaped work (the DOM order change adds and removes nothing), so render cost, memory, network, storage and startup time are unchanged; the desktop table, virtualization and paging paths are untouched, so behaviour with a hundred times more rows is identical. Public surface (UI/index.ts exports, props and types) is unchanged, so no version bump or breaking-change entry is needed. Verification: a new co-located Jest/RTL test file pins the current chevron behaviour first (characterization), then asserts the new order, the desktop placement and the CSS separator contract, since the repo maps CSS modules to identity-obj-proxy and CSS values can only be checked by reading the module file (the pattern used by src/Build.test.ts).
